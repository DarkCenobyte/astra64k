ASTRA v5.1 — Windows fix, September 24, 2026

User report: v1 works; subsequent versions do not start.

Cause identified in the distributed executables:
Starting with v2, replacing -nostartfiles with -nostdlib removed math adapters
normally supplied by MinGW. Symbols such as sinf, cosf, expf, floorf, and pow
were resolved by auto-import to IAT entries in .idata. The generated code then
issued CALL IAT_address instead of an indirect call to the function. .idata is
not executable. No program initializer processes the pseudo-relocations needed
to make this resolution work.

Example from the original v2:
  instruction 0x14000157f: CALL 0x140048418
  destination: cosf entry in .idata, outside any executable section.
v1, linked with the standard libraries, does not have this defect.
v2 is not compressed: UPX cannot explain the initial regression.

Fix:
- Restore the standard math libraries used by v1 (-nostartfiles, default
  libraries + -lm) and remove the winmath.c adapters.
- Disallow auto-import and treat linker warnings as fatal.
- Check the destinations of direct branches before compression.
- Add a local log of startup steps and errors.
- Check window/context/thread creation and the GLSL shaders.

No third-party library installation is required.

Targeted verification:
1. Check branch destinations in the actual binaries listed below.
2. Rebuilding v2 with auto-import disallowed fails on the missing math
   symbols. v5.1 passes with this guard enabled.
3. After UPX compression and decompression, the .text, .data, .rdata,
   .pdata, .xdata, and .reloc sections are identical; the same 94 imported
   functions occur at the same IAT addresses. UPX reorganizes import metadata
   and PE fields, so the decompressed file is not expected to have an
   identical file hash.
4. Six Linux/OSMesa images are byte-for-byte identical to v5:
   2.50, 28.00, 51.40, 72.00, 113.00, and 136.00 seconds.
   Shader compilation/linking and OpenGL states: PASS.
5. The 12 files common.h, art.h, portrait.h, particle_book.h, spectrum.h,
   sky_tracers.h, kirchhoff.h, formula_points.h, pavilion.h, celebration.h,
   synth.h, and voice.h are identical to their v5 versions.
   No scene, lyric, score, or duration change.

Verification limit:
Native execution on Windows was not performed here. Wine cannot initialize
its server in this environment (socket: Operation not permitted). Linux
renderings should not be presented as captures of the new Windows EXE.
The linker defect was observed and removed in the Windows machine code.

User diagnostics:
Run Astra-v5.1.exe normally. If a problem occurs, send the
Astra-v5.1.exe.log file created next to the EXE (fallback: Windows %TEMP%
directory). Astra-v5.1-diagnostic.cmd can run it windowed with --low rendering.
